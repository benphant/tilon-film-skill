# 即梦画布：从导演稿到可恢复生产

本文件负责把详细调度落实到真实节点。使用官方 `dreamina-canvas` CLI；已安装 `dreamina-canvas-cli` Skill 时同时读其任务相关协议。以下命令形态核对于 CLI 1.0.3，执行当天仍以本机 `schema`、帮助及模型查询为准，不把示例版本当永久能力。

## 1. 先确定执行边界

从当前对话记录四件事：交付批次和数量、规格、是否允许生成、预算范围。不要把过去另一批的预算自动转移到新批次。

| 用户当前要求 | Agent 应完成的工作 | 生成边界 |
| --- | --- | --- |
| 只写脚本 | 详细导演稿、时间表、引用计划 | 不创建或运行付费任务 |
| 全部准备好，我来点击 | 创建/编辑可检查草稿，绑定已就绪素材，回读配置，报价 | 不运行视频；生成缺失参考图也需要其范围已获授权 |
| 图片先生成，视频待确认 | 运行已授权图片，待完成后绑定主体及视频草稿 | 不将图片许可扩展到视频 |
| 直接按这批规格生成 | 完成草稿、真实报价、核对已有授权、提交和追踪 | 具体批次与预算已覆盖时继续，不机械重复索要同一批准 |
| 调整提示词/整理画布 | 编辑现有节点，回读内容和布局 | 编辑不等于再生成，避免误带 `--run` |

`confirmationRequired` 是平台消费闸门，不代表必须新增一轮对话。已有用户对该具体批次的明确消费授权，可据此调用确认；没有足够授权才询问。用户尚未看到价格、又只说“看看能不能做”时，不替其批准。无上限授权也不等于任意扩展数量、版本或返修轮次。

## 2. 发现能力、选择画布

可运行的命令片段见 [CLI 操作示例](canvas-cli-examples.md)。先读取版本、schema、目标 profile 的 `auth status`。认证有效则继续；需要登录时调用当前 `auth login`，在用户指定的浏览器打开返回的官方授权链接，再检查认证结果。不因为页面已打开就声称登录成功，不用 `--force` 重置正常会话，不输出凭据。

用户给定画布时先查询它的真实节点。已有任务延续原画布；用户要求独立制作线、确无对应画布或新项目需要隔离时创建新画布。先保存客户端画布 UUID，调用 `canvas create`，从 `data.project` 取 `projectId` 和 `webUrl`。复用时用 `canvas ls` 定位，以 `node find` / `node show` 读取内容；当前版本没有 `canvas show` 或 `node ls`。

创建/选定画布后立即发送其真实 `webUrl`，按用户浏览器偏好打开并尽量复用标签页。后续命令显式传 `--project-id`，避免操作另一个当前画布。浏览器只负责可视检查或 CLI 缺失能力的补充；不能跳过 CLI 中已可用的正式引用、报价和任务查询来盲点 UI。

用 `model find` 解析用户所说的模型别名，或用 `model list --type` 浏览类型；写入 canonical model。逐项核对 mode、画幅、分辨率、时长、数量、素材类型/数量与 prompt 长度。用户要 30 秒横屏时，不因旧模板是 15 秒竖屏而偷改规格；模型不支持就说明差异，不能静默换型号或拆分。

## 3. 从参考图到主体引用

先依据 [人物与连续性](identity-and-continuity.md) 选择已认可素材。要求原创就从零建立新人物；不引用失败视频帧。要求三视图同一张，就交付同图内同一个人的正、侧、背视图，不用三个不同人代替。是否另做单人主图依据实际识别质量，新增生成仍计入已授权范围。

素材来源对应三条路径：

- **已有画布媒体节点**：直接用其 Node ID。需要跨镜复用角色时，可创建 Element；不为“完整流程”重复生图。
- **本地素材**：`resource upload` 显式传项目与稳定资源 UUID，成功后取 `resourceId`；用 `node create image --resource-id ... --import-kind ...` 导入画布，再引用该 Node ID。导入也保存 submit ID；不从本地路径直接伪装成模型引用。
- **新生成参考图**：先保存图片节点，按报价授权生成，等可用成功资源再创建主体或运行下游。只保存上游草稿不能给模型提供人物身份。

Element 的 `--main` / `--auxiliary` 接受裸 Node ID，优先连接当前画布已就绪的图；主图表现身份，辅助图提供侧背、服装或细节。主辅图展开可能占多个模型素材槽，按实际能力核对。绑定后回读 `subjectBindings` 与 `upstreamNodeIds`。

生成节点的两个引用层次必须同时理解：

- `--ref node:<真实节点ID>` 将媒体加入引用集合并建立上游关系。
- `{{node:<真实节点ID>}}` 放在 prompt 里人物/物体出现的位置，将该对象与动作、站位绑定。普通 `@角色名`、只写人物名字或固定 seed 都不建立身份引用。

例如正文是“人物A {{node:...}} 在画面左侧，人物B {{node:...}} 在画面右侧”；工程中替换真实 ID，用户可读稿保留人物编号与名字。场景参考写明“只继承空间和光源”，角色参考写明“继承身份与服装”，避免把多视图排版生成到视频里。

### 按真实来源选择模式

| 输入目的 | CLI mode | 注意 |
| --- | --- | --- |
| 没有媒体参考 | `t2v` | 当前接口不能带引用，包括 Text |
| 单张图片锁首帧，或两张有序首尾图 | `first_last_frame` | 图片决定画幅；两张需相同比例，不能把 Element 当图片帧 |
| 角色主体、多模态参考，或单图但需独立指定画幅 | `m2v` | 当前模型须支持，按展开后的素材类型和数量校验 |
| 纯文字生成参考图 | `t2i` | 有媒体身份参考时转 `i2i` |
| 根据人物主图派生图 | `i2i` | 必须有真实可用的图片/主体参考 |

不能仅凭 `node_` 前缀猜类型。Text 可在兼容 mode 中作为 `--ref` 前导上下文，不能写进正文媒体占位符。首尾帧槽位顺序不由正文引用代替。

目标画布已有来源节点时保留 Node 引用。仅在资产库无来源节点，或用户明确要冻结某次产物时用 `res:<resourceId>`。跨项目先按当前协议显式关联来源，不复制未知 ID 或从临时链接猜存储标识。

## 4. 保存、回读、安排依赖

一段独立生成片段对应一个视频节点；片内 3 秒、5 秒、7 秒子镜头写进同一 15 秒 prompt，不自动变成三次生成。多个独立交付物默认分节点，`count=1`；只有用户需要同节点多候选时增加 count。

保存前冻结 Node ID 与 update ID；创建/编辑不带 `--run`。读回确认真实 `generation` 中的模型、时长、比例、分辨率、outputCount、完整 prompt 与导演稿一致。编辑 generation 是完整替换，提供任一生成参数都需显式 mode，并重传需要保留的 prompt、参数和引用；只改标题/坐标时不传生成配置。

有引用时回读三层：

1. `generation.references[]` 与 `subjectBindings` 的来源 `kind=node`、ID 正确。
2. `upstreamNodeIds` 含预期上游节点；缩略图出现不等于连线存在。
3. 正文保留占位符，`promptParts[].referenceIndex` 指向对应来源；连线存在也不证明 A/B 动作绑定正确。

未验证、缺失或截断的字段明确记录。引用错误先修草稿，不为修线重复生图。`writebackSupported=false` 时遵循阻断原因，不能清空引用绕过限制。

允许预先保存指向尚未就绪节点的引用；运行下游前必须有可用素材。按真实依赖阶段生产：角色主图 → 必要派生图 → 主体绑定/镜头引用 → 视频。无依赖的同批可并行，有依赖的不能只因“赶时间”一起运行。时间轴仅在需要合成时创建，所有来源先就绪并测量实际时长。

默认智能布局。需要整理时读取每个节点的真实 `layout.width/height` 和父组坐标，再按制作线排列，回读确认不重叠；不靠猜固定卡片尺寸移动旧作品，不带 `--run`。

## 5. 真实报价、已有许可与预算

先保存计划，再 `node quote`。逐项核对每个节点均报价成功、`confirmable` 可用、`totalMaxCredits` 为完整批次金额。部分报价不能当整批上限，缺失金额不能按 0；不能用历史单价外推并声称真实报价。

记录一份简洁预算：批次、产物及数量、规格、逐项/总报价、授权原话或会话依据、批准上限、已受理项、是否包含返修。需要新批准时，先把草稿和报价做具体，再问这一项明确的消费决定。已有许可覆盖时简短告知真实报价并执行，不因每张图或平台 token 另问一遍。

运行流程是：保存 → quote → 核对用户授权 → `node confirm --credit-ceiling` → `node run --credit-token`。确认返回的 token 只在内存中传递，不打印、不写 JSON 状态、不进仓库；使用不回显子进程参数的调用器，不启用 shell trace。完整单次调用示例见 [CLI 操作示例](canvas-cli-examples.md#确认并提交的一次性调用)。

价格超过已批准上限、批次扩容、增加版本或未被授权的付费返修时停止该新增消费，给出新旧差额。不能为了通过预算静默降低分辨率、缩短时长、删参考或改变数量。token 到期是技术状态；同一范围的用户许可并不自动失效，但仍需重新核对价格与实际提交事实。

报价与 `creditsAmount` 预扣快照均不等于最终净消费；没有账本事实不声称结算或退款完成。

## 6. 幂等状态与中断恢复

实际运行前，为每个节点生成一个稳定 submit UUID 并落盘；批量参数按节点与 submit ID 等长、同序、一一对应。开始提交前原子写入 `submissionAttempted=true`，只有公开恢复字段进入状态文件，权限限定当前用户。每次运行还记录批准上限、参数/提示词版本与授权范围；不存 provider payload、token、signed URL 或账号配置。

最小状态结构：

```json
{
  "projectId": "真实公开项目ID",
  "submissionAttempted": false,
  "authorizedCreditCeiling": null,
  "items": {
    "V01": {
      "nodeId": "真实公开节点ID",
      "updateId": "本次保存UUID",
      "submitId": "本次生成UUID",
      "operationRef": null,
      "selectedResourceId": null,
      "reviewStatus": "not_reviewed"
    }
  }
}
```

这里的 null 表示尚未获得付费许可；只有明确的有效批准值才能进入提交。它与未知报价都不能按 0 处理。`items` 使用业务键到逐项身份的字典；批次提交标记与批准上限保存在顶层，逐项保留各自 submit ID。

| 观测结果 | 下一步 |
| --- | --- |
| 响应丢失、进程中断、`unknown` | 用原 submit ID 只读查 `operation status/wait`，不重放 create/run、不换 UUID |
| `accepted` / `running` | 继续查询同一任务；受理不是完成 |
| 保存后因缺少消费批准退出 | 保留 partialData 中 nodeId 和 submitId；没有发生生成时按新获得的有效批准继续 |
| `absent` | 记录可能过期，结合节点产物和可得账本核对，不能仅据此断定没有扣费 |
| `rejected` / 素材未就绪 / 参数冲突 | 按结构化 error/validation 修正，只处理未成功项；不原样盲重试 |
| `failed` 且考虑重生成 | 明确这是付费新尝试，确认仍在返修授权内后报价，保留旧任务记录 |
| 查询本身超时 | 服务端任务可能仍在运行，等待预算耗尽不等于生成失败 |

按结构化 `requiredAction`、`reasonCode`、submission/resource 状态判断，不匹配错误文案。保留存在的 `meta.requestId` 供排障；不把所有 response 原样写入工程日志。

## 7. 交付状态必须准确

逐项区分：草稿已保存、提交已受理、资源成功可用、实际审片通过。operation 的资源状态与 node 的状态可能使用不同枚举，依据该命令返回的 schema 解释；不能将空资源列表判定为成功。

预生产交付：画布链接、可复制详细提示词、实际规格、角色/素材映射、真实报价、哪些尚未提交。生成交付：每项终态、可用资源与用户请求的文件；只有观看并听取真实输出才可说审片通过。用户明确要求跳过审片时可以交付“生成完成，未审片”，不把检查强加为新增生成或无限返修。

下载仅在任务需要文件时进行，使用官方 `resource download`，检查字节数、格式、实际时长及返回校验值。源文件/状态/参考素材放制作工程，成片进入用户指定交付目录，不把私人素材、账号、绝对个人路径或运行记录推到公开技能仓库。
